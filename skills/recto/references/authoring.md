# 内容生成与图解

本文只在用户授权生成、补充或改写内容时使用。授权是局部时，只把流程应用到点名范围；其余正文仍按 Recto 的转换模式处理。纯 Markdown 转 PDF／Word 不读取本流程，也不做研究、补图或去 AI 腔改写，因为那会把版面任务变成未经授权的写作任务。

## 1. 先定写作对象

```text
是否已有原始材料？
├── 是
│   ├── 既有事实、原文论证、题号和数据 → 保留并核对
│   ├── 可重组的解释与结构 → 可重排，但不得改变事实或结论
│   ├── 用户点名补充的部分 → 可生成，并标明新增示例／说明
│   └── 仍不确定的内容 → 列为疑点或查证，不补造
└── 否
    └── 只写用户主题范围内能被推导或核实的内容；缺失依据时说明缺口
```

先从上下文确定用途、读者基础、范围和成功标准；已有答案直接沿用，只问会改变交付结果的问题。用一两句说明本次将生成什么、使用哪套版式和输出格式，然后继续，不把编辑说明当审批。

写作前建立核对清单：数学条件、定义域、记号、量纲、推导步骤、结论、编号、图表来源。可变外部事实用一手资料核实并记录来源与日期；数学证明逐步验证，不以引用替代推导检查。没有依据的数值、实验结果、作者、文献和机构不能补造。研究只服务被授权的新内容；不因为原文存在而自动扩展成资料收集任务。

## 2. 组织正文

先组织内容，再考虑图和版面。讲义通常先交代问题与必要概念，再给结论、条件、推导和适量例题；按主题取舍，不机械凑栏目。标题连读应呈现主线，正文每段提供解释、证据或推理，不能只复述标题。

对被授权改写的段落，优先保留原文中正确的术语、条件和例子；改写目标是让推理更容易跟随，不是换成另一篇文章。新增例子标明「示例」，不伪装成用户提供的原题或实验结果。

## 3. 决定是否配图

```text
一段清楚文字能否比图更准确？
├── 是 → 用文字，不配图
└── 否
    └── 图是否能让读者看出文字难以同时呈现的关系？
        ├── 否 → 不配图
        └── 是 → 按下表选择，并保存可编辑图源与数据
```

| 关系 | 表达 |
|---|---|
| 条件分支、算法步骤、方法选择 | 流程图；判断边写条件，循环写退出条件 |
| 状态与合法转换 | 状态图；不把时间顺序画成因果 |
| 概念包含与层级 | 树图或层级图 |
| 部件间信息或物理联系 | 结构图；明确边代表什么 |
| 函数、误差随参数变化 | 由真实函数或数据生成的曲线图，标注坐标、单位、范围和假设 |
| 相同指标下比较对象 | 简洁表格或柱图 |
| 两三个定义或单一事实 | 正文 |

流程图先写节点、边和条件，再绘制；一次只表达一条主线，节点过多时按可独立理解的部分拆分。箭头准确接到节点边缘，不穿过标签；成品字号仍易读。灰度打印可区分主要关系，颜色不能作为唯一编码；使用白底、黑灰线条和统一字重，不加渐变、发光、装饰图标、圆角卡片墙或无意义三栏总结。

流程关系可用 Mermaid／Graphviz，函数和实测数据用 Matplotlib 等绘图库。保存可编辑图源与数据，不只保存截图；严谨数学图必须由真实函数、坐标或数据生成，图不能替代证明。默认把 SVG 用于 Typst；跨格式图提供足够分辨率的 PNG 兼容稿。Word 中图本身作为图片，不声称节点可编辑；数学公式仍用 OMML。

图注说明读者应看出什么，并写必要条件或来源，不重复整段正文。

## 4. 去 AI 腔检查

只检查被授权生成／改写的内容。目标是清楚、具体、可核实，不承诺规避 AI 检测，也不为了「像人写」加错字或口语。

按顺序检查：

1. 删除无信息的开场、口号、拔高意义和空泛评价；把抽象概括落到对象、条件、操作和结果。
2. 删除虚构数字、引用或经历；无来源的强断言改成与证据相称的说法，或明确指出缺口。
3. 检查机械三段式、连串「首先其次最后」、同义复述和过度小标题；按推理关系衔接。
4. 「值得注意的是」「这意味着」「不仅……而且」「本质上」不是禁词；若删除后含义不变，就删。必要的数学转折、严格条件、定理措辞和术语不能为文风牺牲。
5. 匹配读者语气：教材解释概念并展示推理，正式材料陈述事项与依据；不混入营销腔，也不代替作者表态。
6. 不靠加字、缩字号、填充段落或装饰图塞页；章节末页可以留白。异常大空白先判断是分页问题还是内容自然结束。

## 5. 交付前检查

先核对事实、公式和论证，再检查措辞与结构，最后逐页看图表和版面。确认图与正文一致、引用有落点、示例未冒充来源，生成过程中的提示词、待办和编辑口令不进入正文。

最终答复只简述实际增补的内容和需要用户决定的疑点，不输出长篇内部检查报告。
