# Recto

先判定用户授权的是「版面」还是「内容」，再把同一份内容源导出为固定版式和可编辑版本。先定权限，是为了避免在格式转换中改动用户正文。

## 首次使用或插件安装引导

用户要求安装、配置、检查 Recto，或运行插件 onboarding 时，只执行 [依赖检查与安装](references/setup.md)，完成后报告实际可用的引擎与字体，不要求提供正文，也不生成文档。普通排版请求在导出前执行同一检查；缺项时单独走安装流程，复查通过后接着完成原任务。

## 1. 判定内容权限

按顺序走下面流程，命中即停：

```text
用户是否没有给正文，只给主题并要求成文？
├── 是 → 生成模式：全文可组织、补写、查证、按需配图、做去 AI 腔检查
└── 否
    └── 用户是否明确要求生成、补充、扩写或改写内容？
        ├── 是
        │   ├── 请求是补一个例子、画图或修改部分内容 → 局部生成模式
        │   └── 请求是成文或全文改写 → 生成模式
        └── 否 → 转换模式：只做格式、层级与版面整理
```

| 模式 | 必做 | 禁止 |
|---|---|---|
| 转换模式 | 保留原文、公式、表格、图注、编号和标题；仅做语法适配、层级整理和版面 QA | 内容提炼、扩写、补充研究、自动配图、去 AI 腔改写 |
| 局部生成模式 | 只对点名段落／章节启用 [内容生成与图解](references/authoring.md)；其余内容按转换模式 | 把局部授权扩大到全文；用户只要图时不顺带改文字 |
| 生成模式 | 全文按 [内容生成与图解](references/authoring.md) 组织、核对、配图和检查措辞 | 无依据补造事实；为了填页添加图或段落 |

「整理一下」「排版」「导出」「原样转成」默认都是转换模式。原文零散或语言生硬不是升级为生成模式的理由；交付后最多简短提建议。生成权限同时受动作和范围限制：补例子不等于重写原文；只有无法从材料推断、且实质阻碍交付的缺口才询问。

**课程讲解**：生成或改写首次学习讲义、考前复习或指定作业讲解时（包括给作业附件只说“制作讲解”），先从技能列表定位并读取 `$study-notes` 及其命中的参考文件，由它确定教学顺序、题目覆盖与答案语言；完成稿再回到本 skill 转换导出。插件包含此写作依赖；单独安装时若缺少它，先说明缺项并保留材料。已有讲解稿的纯排版直接继续转换，不重新组织内容。

## 2. 选择既定样式

| 判断 | 样式 |
|---|---|
| 用户已有明确选择 | 沿用该样式 |
| 点名 `reference`／清爽课程讲义 | `reference` |
| 用户明确点名 `gbt9704`／国标正文，或要求中文正式文字、表格、附件／附录版式 | `gbt9704` |
| 其余未指定样式的请求 | `reference` |

不新增第三套风格。用户已有选择时沿用，不重新采访。`gbt9704` 默认只做正文、表格和附录，不包含红头、发文字号、主送机关、署名、日期、印章或版记，也不为这些元素留空；这是用户选定的正文样式范围。

样式细节见 [版式约定](references/styles.md)。

## 3. 建立共同源

三格式共用一份语义化 Markdown：可选 YAML 标题、正文、LaTeX 数学、标题层级、普通表格、图片、脚注、链接、行内代码和代码块。共同源是唯一正文副本；LaTeX/PDF 与 Word 都由它独立导出。这样用户改正文时不会遇到三个版本互相分叉。

转换模式的固定规则：

- 保留原有标题与编号；源稿无标题就不新增可见标题，YAML `title` 可以省略。可见标题会改变文档的呈现对象和层级，转换请求没有授予这项内容变更。
- 保留链接目标以及代码的字面内容、缩进和语言标记；不能为绕过字体或溢出诊断把代码改成普通正文。长行只在版面上折行，不改共同源。
- 保留数学条件、定义域、公式、论证、题号、单位、表格内容和图注。只把 Markdown／LaTeX 语法适配为导出器可理解的形式。
- 从 PDF／图片提取内容时同时查看原页；文本提取常丢失上下标、根号、分式和矩阵，必须用原页校正。
- 疑似数学或事实错误只向用户指出具体位置和疑点，不擅自修正。

语法和受限语法见 [源文件与导出](references/export.md)。可从 `assets/examples/` 取最接近的示例，但必须替换全部样文，不把示例内容带入用户文档。

## 4. 导出

默认交付 **Markdown、LaTeX 和 PDF**；用户要求 Word 时加 `.docx`，明确只要某些格式时按要求增减。旧请求中的 `typ` 格式不再可用；提示用户改用 `tex`，并说明 Typst 链路已迁移为 LuaLaTeX。图片统一放在 `media/`，LaTeX 源文件放在 `latex/`；两个源格式共用一份图片，不再复制第二套。`latex/fonts/` 只保留本次选用的开源字体族及其许可证，不复制系统专有字体。目录名使用这些英文名称，不用“素材”“交付”“工作文件”等中文目录名。

最终目录只保留一份 Markdown、用户需要的成品及其必要资源。默认不生成 ZIP、独立重编译说明、导出报告、QA 文件或预览缓存；重编译命令写入 `document.tex` 顶部注释。用户明确要求压缩包时才额外打包。生成和验收过程使用交付目录以外的工作目录；验收完成后清理本轮产生的中间文件，不把旧稿、复制的源文件或整个字体库留给用户。已有目录只清理能确认由本轮流程产生或用户点名的生成文件，不按后缀批量删除未知文件或原始材料。

1. 有 `mcp__codex_app__load_workspace_dependencies` 时取得捆绑 Python，否则使用本地 Python 3.10+。按用户实际请求的格式运行 `scripts/doctor.py --style <样式> --formats <formats>`；格式包含 PDF 时检查 `latexmk` 与 TeX 包，否则不检查或安装它们。请求格式的依赖缺失或过旧时按 [安装流程](references/setup.md) 补齐再复查，不直接以“缺依赖”结束任务。有原字体就沿用，缺少时使用随包开源字体，或使用 `--bundled-fonts` 强制随包字体；导出前简短说明替代。用户明确要求原字体时暂停并指出具体缺项，不能悄悄替换。
2. 把 `RECTO_ROOT` 设为当前已安装 `SKILL.md` 所在目录，使用第 1 步确定的样式、格式和 Python 导出。每次尝试使用新的外部报告路径，替换示例中的对应值与路径：

   ```sh
   "$RECTO_PYTHON" "$RECTO_ROOT/scripts/export.py" content.md \
     --style reference --formats tex,pdf,docx \
     --output /absolute/output/folder \
     > /absolute/qa/export-attempt-1.json
   ```

   只运行当前 Recto skill 自带的 `export.py`；编译引擎相同不能保证模板相同，因此不得另写 Pandoc/LaTeX 管线，也不得为绕过失败修改随包脚本或模板。导出脚本离线运行，联网安装只发生在独立安装流程中；LuaLaTeX 按源文件内嵌路径读取随包字体。需要 Word 时按安装流程把使用的随包字体安装到用户字体目录。导出器在编译前检查生成的 TeX 包含完整的正式样式和字体设置。

3. 导出退出码非 0 时，本轮报告作废：只能修复可处理的依赖或输入后从同一公开入口重新导出，或保留源稿并报告具体阻塞项。不得编辑、复用失败前的旧成功报告，也不得把旧目录文件当作本轮成品。导出成功后检查退出码为 0、标准错误无未处理诊断、报告确实来自本次重定向的 stdout。
4. 用同一来源、样式、格式、字体选项和输出目录做完整性验证，另加 `--verify-report`；该验证只读成品、不重编译、不需要 TeX：

   ```sh
   "$RECTO_PYTHON" "$RECTO_ROOT/scripts/export.py" content.md \
     --style reference --formats tex,pdf,docx \
     --output /absolute/output/folder \
     --verify-report /absolute/qa/export-attempt-1.json
   ```

   退出码为 0 且 `template_verified: true` 才通过：检查当前导出器和模板、原始或导出后的共同源、请求选项、成品及资源是否与本次成功导出一致。验证失败按第 3 步处理。正文修正回到共同源后重新导出；正式版式的变更遵循用户已授权范围，导出失败不构成改版授权，不能靠手改成品后沿用报告交付。

   用户只要 PDF 或 Word 时，先在工作目录完成上述导出与验证，再交付所需文件。复制或改名后逐个比对已验证文件的 SHA-256；保留工作目录中的共同源供复验，不把它或报告加进用户未要求的交付。完整目录可整体移动后复验。

## 5. 验收

按用户请求的格式验收：

- PDF：逐页渲染并检查字号、中英文混排、页边距、公式溢出、表格跨页、标题孤行、图注与页码。只交付 PDF 时在工作目录完成 QA，不把 TeX 源放回成品目录。
- DOCX：确认公式为 OMML，再用文档技能的渲染脚本和捆绑 LibreOffice 逐页检查。渲染不可用时标明视觉验收待办；本轮没有用原生 Word 打开核对时，单独说明原生 Word 未验证。
- 仅源码：检查源码、公式映射、图片引用和导出日志。没有 TeX 引擎时标明未编译，不为源码交付强制安装编译器；有引擎时也只按实际完成的编译和页面检查报告验证范围。

最后核对源内容、公式数量与引用对应关系。含引用时实际核对文内跳转目标和外链；含代码时检查中文、特殊字符、缩进、跨页及文本选取，不以导出成功替代保真验收。生成模式还要完成 [内容生成与图解](references/authoring.md) 的交付前检查。

交付 Markdown 与 TeX 时检查两者及图片引用；同时交付 PDF 与 `latex/` 时，从最终目录用 `latexmk` 重新编译并比较页面，确认移动和去重没有破坏路径；若重编译或移动改变了报告记录的成品字节，重新走官方导出与验证。若只是整理已有成品，保留 PDF 原文件；不把目录整理说成内容或版式改写。确认交付完整后，移除可确认无用的旧导出、ZIP、重复图片、预览和 QA 文件。

## 交付边界

PDF 是固定版面的阅读与打印版本；`latex/document.tex` 内嵌版式与字体选择，可编辑并重新编译；DOCX 由 Pandoc 独立转换为 OMML，不需要 TeX，其文字、公式和表格可编辑，但 Word／LibreOffice 的字体和分页机制可能使行、页不同。国标横向表格在 PDF 中保留纵向纸张内旋转，Word 中使用可编辑的横向节；不能把 Word 版本称为与 PDF 逐页一致，或称为完整国标公文认证。

交付时列出用户要求的文件，不额外交付导出报告。完整性验证用于发现流程偏离或文件变化，不能鉴别伪造报告，也不替代逐页视觉 QA；未用原生 Word 打开时，不声称原生 Word 验收。
