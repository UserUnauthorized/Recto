# Recto

先判定用户授权的是「版面」还是「内容」，再把同一份内容源导出为固定版式和可编辑版本。先定权限，是为了避免在格式转换中改动用户正文。

## 1. 判定内容权限

按顺序走下面流程，命中即停：

```text
用户是否没有给正文，只给主题并要求成文？
├── 是 → 生成模式：全文可组织、补写、查证、按需配图、做去 AI 腔检查
└── 否
    └── 用户是否明确要求生成、补充、扩写或改写内容？
        ├── 是
        │   ├── 请求是补一个例子、画图或修改部分内容 → 局部生成模式
        │   └── 请求是成文或全文改写 → 生成模式
        └── 否 → 转换模式：只做格式、层级与版面整理
```

| 模式 | 必做 | 禁止 |
|---|---|---|
| 转换模式 | 保留原文、公式、表格、图注、编号和标题；仅做语法适配、层级整理和版面 QA | 内容提炼、扩写、补充研究、自动配图、去 AI 腔改写 |
| 局部生成模式 | 只对点名段落／章节启用 [内容生成与图解](references/authoring.md)；其余内容按转换模式 | 把局部授权扩大到全文；用户只要图时不顺带改文字 |
| 生成模式 | 全文按 [内容生成与图解](references/authoring.md) 组织、核对、配图和检查措辞 | 无依据补造事实；为了填页添加图或段落 |

「整理一下」「排版」「导出」「原样转成」默认都是转换模式。原文零散或语言生硬不是升级为生成模式的理由；交付后最多简短提建议。生成权限同时受动作和范围限制：补例子不等于重写原文；只有无法从材料推断、且实质阻碍交付的缺口才询问。

## 2. 选择既定样式

| 判断 | 样式 |
|---|---|
| 用户已有明确选择 | 沿用该样式 |
| 点名 `reference`／清爽课程讲义 | `reference` |
| 用户明确点名 `gbt9704`／国标正文，或要求中文正式文字、表格、附件／附录版式 | `gbt9704` |
| 其余未指定样式的请求 | `reference` |

不新增第三套风格。用户已有选择时沿用，不重新采访。`gbt9704` 默认只做正文、表格和附录，不包含红头、发文字号、主送机关、署名、日期、印章或版记，也不为这些元素留空；这是用户选定的正文样式范围。

样式细节见 [版式约定](references/styles.md)。

## 3. 建立共同源

三格式共用一份语义化 Markdown：可选 YAML 标题、正文、LaTeX 数学、标题层级、普通表格、图片和脚注。共同源是唯一正文副本；Typst、PDF 和 Word 都由它导出。这样用户改正文时不会遇到三个版本互相分叉。

转换模式的固定规则：

- 保留原有标题与编号；源稿无标题就不新增可见标题，YAML `title` 可以省略。可见标题会改变文档的呈现对象和层级，转换请求没有授予这项内容变更。
- 保留数学条件、定义域、公式、论证、题号、单位、表格内容和图注。只把 Markdown／LaTeX 语法适配为导出器可理解的形式。
- 从 PDF／图片提取内容时同时查看原页；文本提取常丢失上下标、根号、分式和矩阵，必须用原页校正。
- 疑似数学或事实错误只向用户指出具体位置和疑点，不擅自修正。

语法和受限语法见 [源文件与导出](references/export.md)。可从 `assets/examples/` 取最接近的示例，但必须替换全部样文，不把示例内容带入用户文档。

## 4. 导出

默认交付 `.typ` 与 `.pdf`；用户明确要 Word 时加 `.docx`。保留完整本地源文件与图片，提供可重新编译的成品包；字体不随包分发。

1. 调用 `mcp__codex_app__load_workspace_dependencies` 取得 Python。确认本机 `pandoc`、`typst` 和所需字体；缺少依赖或字体时明确报告，不静默替换成不同视觉。
2. 运行：

   ```sh
   "$RECTO_PYTHON" /absolute/path/to/recto/scripts/export.py content.md \
     --style reference --formats typ,pdf,docx \
     --output /absolute/output/folder
   ```

   `$RECTO_PYTHON` 指向依赖加载器返回的 Python。不需要 Word 时省略 `docx`。脚本使用本地 Pandoc 和 Typst，不下载字体或依赖。

3. 检查命令退出状态、诊断输出和 `export-report.json`。导出器遇到转换警告会停止；先解决诊断，不能把目录里上次留下的文件当成本轮成功输出。
4. 修复共同源或样式后重新导出受影响格式。只改 Typst 精细版式时，明确说明该改动不会自动同步到 DOCX。

## 5. 验收

PDF 必须逐页渲染并检查：字号、中英文混排、页边距、公式溢出、表格跨页、标题孤行、图注与页码。DOCX 公式必须是 OMML，不能以截图冒充可编辑公式；再用文档技能提供的渲染脚本和工作区捆绑的 LibreOffice 逐页检查。原生 Word 未实测时，明确说未实测，不声称已在 Word 验证。

最后核对源内容、公式数量与引用对应关系。生成模式还要完成 [内容生成与图解](references/authoring.md) 的交付前检查。

## 交付边界

PDF 是固定版面的阅读与打印版本；`.typ` 可编辑并重新编译；DOCX 的文字、公式和表格可编辑，但 Word／LibreOffice 的字体和分页机制可能使行、页不同。国标横向表格在 PDF 中保留纵向纸张内旋转，Word 中使用可编辑的横向节；不能把 Word 版本称为与 PDF 逐页一致，或称为完整国标公文认证。

交付时列出文件和源文件包，并区分已验证与未验证部分。不要把结构检查、导出成功或页面可见当成逐页视觉 QA 的替代。
