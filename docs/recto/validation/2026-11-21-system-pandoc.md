# 使用现有 Pandoc 导出 L19

## 0.5.8 的 Web 下载

L19 原会话使用外部 Pandoc 3.9.0.2 与正式排版包生成 PDF。Chrome 从预览下载的文件为 399,631 字节，SHA-256 为 `fe1012d9cf9c066ae73d061a18280b9e3a46cfcd34dd760bd9d77208a80e57fb`。原会话重新读取下载路径，结果与本机一致。首次回复中的大小和摘要均有误，原生成目录及报告已不可访问，无法把下载副本追溯到该报告。下载件的 16 页均可渲染，第 6.2 节的书签在第 9 页，保留了指数符号。

## 系统 Pandoc 兼容测试

用官方 macOS arm64 Pandoc 3.1.11.1 复现了版本检查拦截原稿。该版本提供 `--highlight-style`，不支持 `--syntax-highlighting` 或 `--table-caption-position`。用含表题的最小输入对照实际 LaTeX 输出，旧版默认生成表上标题。L19 只有一张无表题的表格。

从公开导出入口使用该版本、随包字体、LuaLaTeX 1.24 及 latexmk 4.89。开发机的隔离 TeX 树补充了旧 Pandoc 模板加载的 selnolig 宏包。L19 原始 Markdown 的 SHA-256 为 `959dd6951c07cdd5d2ae00190c2b069b068401ff74c0484176b5b5d017f6c5f9`。旧版导出 16 页，源稿解析出 384 个数学节点。逐页渲染并核对第 9 页书签，正式报告复验通过。技术样例与 GB/T 例稿也完成了 PDF 导出与复验。

reference 稿确有表题且旧 Pandoc 缺少表题位置选项时，测试确认导出器明确报告缺项。请求 DOCX 仍按既有版本要求检查。候选单技能包内有 45 个文件，其中没有 Pandoc 二进制。

## L19 原会话的候选版

在独立解包副本中仅替换 doctor.py 和 export.py。Web 原会话使用 /usr/bin/pandoc 3.1.11.1、LuaLaTeX 1.18.0 和 latexmk 4.86，系统已提供 selnolig。doctor 和正式报告复验均成功。独立下载原报告，核对了原 Markdown 的 SHA-256、运行版本，以及报告覆盖的 31 个实现、模板与资源文件的本地摘要。

预览按钮取得的 PDF 为 399,620 字节。为核实原始成品，原会话从成功的生成目录取回复验文件，归档后读取 PDF 字节，以 JSON 附件传输。独立解码、计算 SHA-256 后与原报告中的 document.pdf 条目一致：354,160 字节，`9c1350228dfcb39308e5e63269249374ff2de9f42133b52db2ada3ee28f8734f`。PDFium 在 1.25 倍倍率下逐页比较预览下载件和原件，16 页的像素全部相同；实际原件的第 9 页书签保留指数。本轮只验证候选实现，线上正式插件仍为 0.5.8。
