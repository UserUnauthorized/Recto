# Web 自学讲义只交付 Markdown

## 原会话与下载探针

L19 原回复只链接了 Markdown。应用户要求在同一会话追查时，它报告此前读取字体遇到 `Resource not readable`，可见历史里没有 doctor、export 或复验的命令、退出码或日志。

该会话随后报告的**本轮探针**结果如下。这些观测不能反推首次运行时的网络状态。

- 插件版本为 0.5.6。资源清单可列出导出脚本和 OTF，但 Python 未取得完整字节。宿主归档和同版本 GitHub Release 的 ZIP 与校验文件都在执行环境报 `Temporary failure in name resolution`。本轮没有运行官方导出器。
- Pandoc 3.1.11.1 低于所需的 3.9。latexmk 4.86、LuaHBTeX 1.18.0 可运行。原稿仍可读取，其大小与 SHA-256 和本地取回的文件一致。

## 本地导出与回归

在独立目录下载两个正式版本的 `recto-skill.zip`，分别核对该标签的 `SHA256SUMS`。0.5.6 与 0.5.7 的 ZIP 解包后只有 `references/authoring.md` 不同。0.5.6 包中的 `export.py` 为 27,256 字节，FandolSong-Regular.otf 为 4,947,904 字节，和云端清单相符。

在 Pandoc 3.9.0.2、latexmk 4.89、LuaLaTeX 1.24.0 下，从 0.5.7 正式包运行 doctor 通过。用原稿、reference 样式、随包字体和 `--formats tex,pdf` 运行公开入口，退出 1。编译日志定位到第 6.2 节标题。Pandoc 在书签文本中用 `\^{}` 表达指数的字面量 `^`，hyperref 发出 `Token not allowed in a PDF string`。这是原稿到达编译阶段后可复现的独立故障。

将同一标题放入已有公开入口回归，在旧模板上得到相同错误。修正共享模板中的 PDF 字符串处理后，运行以下检查：

- `python -m unittest test_delivery.DeliveryTests.test_math_notation_comments_and_literal_percent_still_export test_template`（在 `checks/recto` 下）：4 项通过。回归同时核对实际书签保留指数符号及 Word 原生公式数量。gbt9704 单页样例的书签也正确保留 `x^2`。
- 原 L19 Markdown 经公开入口导出 16 页，`--verify-report` 返回 `template_verified: true`。检查了 16 页渲染及第 9 页公式标题，PDF 书签保留字面指数。用交付目录的 TeX 重编译，16 页分别以相同缩放渲染后像素一致。
- 两个 skill 均通过 `scripts/skills.py check` 和 `package`。修正后的 Recto 单技能包解到全新目录，使用包内入口重新导出同一原稿并通过复验。插件打包测试逐字节核对随包资源。

## 恢复流程走读

有挂载目录时直接使用。只提供文本预览时先取同包归档；已确认官方来源和版本时可取同标签发行物并校验摘要。网络不可用时用附件传入对应归档，提前检查命令版本，一次列出需要离线补齐的文件。缺少执行能力、身份无法确认或校验不符时保留源稿并准确报告阻塞。明确只要 Markdown 的请求跳过 PDF 检查。

本次云端验证止于下载探针，未在 Web 环境用附件跑通完整导出。修改和成品验证均在本地工作树完成。
