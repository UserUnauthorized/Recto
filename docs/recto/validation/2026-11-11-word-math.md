# Word 数学兼容性验收（Issue #4）

日期：2026-11-11。基线：`1560c01`。输入为未改写的 `skills/recto/assets/examples/reference.md`。使用当前公开入口 `export.py --style reference --formats tex,pdf,docx`；旧 issue 中的 `typ` 已在独立迁移中改为 `tex`。本轮没有修改 PDF 引擎、样例正文或字体文件。

## 修复与范围

- Pandoc 3.9.0.2 没有把 reference.docx 的 `m:mathPr` 复制到最终文档。数学字体改为在最终 DOCX 写入，元素顺序遵循 OOXML；最终值与 JSON 的 `fonts.word_math` 一致。
- 旧实现给空 run 加 `m:aln`，Word 与 LibreOffice 都没有按源对齐。仅把标记移到后一个 run 也未修复 LibreOffice。改为按 Pandoc 的非文字 `&` 分成原生 OMML 列，交替右／左对齐；转义的 `\&` 保留。正文和脚注使用同一处理。
- 空列需要 `m:nor` 的普通文本空格，否则 LibreOffice 会误读单元格并丢行。源中的 `\quad` 等空白还需 `xml:space="preserve"`，否则 LibreOffice 会 trim 掉续行缩进。两项均由实际渲染反例确认。
- 仅在给 Word 的数学 AST 副本中把 `\square` 适配为 U+25A1，避开 Pandoc 产生的 Emoji 候选 U+25AB。Markdown 和 LaTeX 保留原数学源。

## 原生应用与逐页结果

环境：macOS；Pandoc 3.9.0.2；Microsoft Word for Mac 16.114.4；工作区捆绑 LibreOfficeDev 26.8.0.0.alpha0。Word 使用“最适合打印”的本地 PDF 导出；LibreOffice 使用仓库 `render_word.py` 与 documents skill 的 `render_docx.py`。LuaLaTeX / latexmk 复用前次验证的隔离 TeX 树，未安装新依赖。

Word、LibreOffice 各 4 页全部查看；核对正文、上下标、积分、向量与范数、矩阵、脚注、图表、图注、页码和页面边界。修复前 LibreOffice 原样复现 (1.4) 等号横坐标不一致；最终结果：

| 核对项 | Word | LibreOffice |
|---|---|---|
| (1.4) 三个等号 x 坐标 | 179.44 / 179.44 / 179.44 pt | 206.70 / 206.70 / 206.70 pt |
| (1.7) 第一行等号 / 第二行显式空白起点 | 223.63 / 223.63 pt | 242.55 / 242.55 pt |
| 证明方框 | U+25A1，CambriaMath | U+25A1，LiberationSerif-Italic |
| Emoji 字体 | 无 | 无 |

原始 Markdown 不含文字 `&`，最终 DOCX 数学文本没有泄漏对齐标记。Word PDF 的文本提取会把两处三阶导数的字形误解码为 `&`；对应位置已按页面图像确认是三撇，不能用该 PDF 的文本字符计数断言符号显示错误。

数学对象仍为 66 个原生 OMML。全部原有 `w:t`、图片字节和规范化 Markdown 的 66 个数学节点分别与基线／源稿一致。完整三格式导出的所有 `word/*.xml` 与原生 Word 校样对应的 DOCX 逐字节一致。LuaLaTeX PDF 为 4 页，另逐页查看。

## 字体配置与实际替代

最终 DOCX 的 `m:mathFont` 与报告均为 `New Computer Modern Math`。本机系统字体枚举未检测到已安装的 NewCM；Word 本轮实际使用私带 CambriaMath，LibreOffice 使用其自身数学字体替代。**设置一致不等于渲染字体一致。**

新增 `word_font_note` 说明配置、编辑端可用性和未测量实际回退的边界；未检测到字体时提示安装随包字体，明确 DOCX 不嵌入随包字体。`font_substitutions` 记录导出配置选择，不声称是目标编辑器的真实回退记录。本轮保留现有字体选择策略，没有为验证而安装字体掩盖缺字体场景。
