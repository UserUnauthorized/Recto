# Codex 插件与随包字体验收

环境：macOS，Codex 桌面捆绑 CLI，Pandoc 3.9.0.2、Typst 0.15.1。开发在独立工作树进行。

## 插件安装

- 根 `plugin.json` 使用 Agent Plugins 1.0.0 格式，插件 `recto`，版本 `0.2.0`。
- `.agents/plugins/marketplace.json` 定义 `recto` Marketplace，插件源为仓库根 `./`。
- 在隔离的 `CODEX_HOME` 中，从最终 ZIP 解出的干净目录添加 Marketplace；`plugin add recto@recto --json` 成功，`plugin list --json` 返回 `installed: true`、`enabled: true`、版本 `0.2.0`。
- ZIP 含 41 个文件，包含 skill、字体、许可证、图标及原样式预览，不含 `.git`、仓库脚本、归档或导出缓存。独立 skill 仍可单独打包。
- 设置引导指向包内 Recto skill 的安装分支。已走读“只配置环境”与“补依赖后继续原转换”的指令；未声称实测桌面 UI 的新会话／现有会话 onboarding 按钮。

## 首次运行与错误路径

- 新建空虚拟环境后，检查器退出 1，准确报告缺少 `docx` 与 `lxml.etree`。
- 在该环境按 `requirements.txt` 安装，实际得到 python-docx 1.2.0、lxml 6.1.3；复查退出 0，再从解包的插件完成真实三格式导出。
- 三个自动化用例覆盖空 PATH 缺引擎时的诊断、原字体优先／缺少随包字体时报错、18 个字体及许可文件的 SHA-256。
- 未卸载主机引擎来重复安装 Pandoc／Typst；检查到了现有版本。Windows、Linux 的依赖安装路径未实机执行。

## 字体与导出

测试 `reference`、`gbt9704` 两套样例，每套分别在默认原字体环境，以及 `TYPST_IGNORE_SYSTEM_FONTS=true`、`TYPST_IGNORE_EMBEDDED_FONTS=true`、空 `TYPST_FONT_PATHS` 环境下导出。

| 条件 | PDF | DOCX 经 LibreOffice 渲染 | OMML |
|---|---:|---:|---:|
| 原字体讲义 | 4 页 | 4 页 | 66，与源公式数一致 |
| 随包字体讲义 | 4 页 | 4 页 | 66，与源公式数一致 |
| 原字体国标正文 | 5 页 | 5 页，后两页横向节 | 0 |
| 随包字体国标正文 | 5 页 | 5 页，后两页横向节 | 0 |

- 已查看全部 PDF 和 Word 渲染页面，检查中英文、公式、表格、附件、页码与页面边界。未发现缺字方框、溢出或裁切；LibreOffice 的数学字形与分页仍不同于 Typst。
- 原字体 PDF 与此前确认的两份成品在 100 DPI 全页渲染后逐像素一致。
- New Computer Modern Math 常规／粗体沿用最初本地样张的原文件，保留其 GUST 许可和文件哈希。Fandol 0.3、Liberation Serif 2.1.5 从官方上游取得，未改名、改字形或子集化。
- DOCX 中配置了字体，但 LibreOffice 会使用自身数学字体替代；其渲染 PDF 可见 OpenSymbol / LinuxLibertineGI。不能把配置名当成编辑器实际使用字体的证明，也未在原生 Microsoft Word 验收。
- 将随包字体版本的源文件 ZIP 解压到另一目录，禁用系统及 Typst 内置字体，运行 `typst compile --font-path fonts document.typ rebuilt.pdf` 成功。
- 导出目录中预置的无关 `fonts/unrelated.txt` 没有进入交付 ZIP；仅打包本 skill 的字体清单。
