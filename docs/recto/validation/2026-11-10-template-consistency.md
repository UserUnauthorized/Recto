## 问题与修复范围

一份实际讲义由 LuaLaTeX 生成，但交付源码另用了 `ctexart`、默认标题、2 字缩进和不同数学字体，没有完整采用 Recto 的正式版式。相同编译引擎不证明采用了相同模板。

- Recto 和 study-notes 明确要求使用当前 skill 自带的 `export.py`；缺依赖、输入不支持或检查失败时修复同一路径或报告阻塞项，不能自行换模板、修改随包实现绕过失败。
- 在发布 TeX 或编译 PDF 前检查生成源包含正式 common、所选样式和字体设置。缺失时停止，旧 TeX 保持不变。
- 复用已有 stdout JSON 报告记录导出器、模板、共同源、请求选项及成品和资源的哈希；新增 `--verify-report` 只读复验，不探测或调用 Pandoc/TeX，不新增依赖。报告保存在工作目录，不改变默认成品集合。
- 报告只用于发现流程偏离及文件变化，不提供签名或防伪保证。每次导出使用新的 stdout 报告路径并检查退出码，失败后的旧成功记录不能作为本轮证据。视觉 QA 仍独立执行。
