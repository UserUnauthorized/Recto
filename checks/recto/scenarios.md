# Recto 人工行为检查

这些场景用于对照 `skills/recto/SKILL.md` 和 `references/authoring.md` 走读预期行为，不是自动化测试，也不证明真实渲染结果。

## A. 忠实转换

请求：「把这份 Markdown 排成 PDF，不要改内容。」

- 进入转换模式，默认 `reference`。
- 输出 `.typ` 和 `.pdf`；不自动输出 DOCX。
- 不补标题、例子、图、引用或研究；无源标题时成品没有新增可见标题。
- 只做语法适配、层级整理和逐页 PDF QA；疑似错误只提示。

## B. 全文生成

请求：「根据这三份资料写一份数学复习讲义，并导出 PDF 和 Word。」

- 进入生成模式，默认 `reference`。
- 读取 authoring 流程；先核对原始材料、公式和事实，再组织正文。
- 只在图比文字更能说明关系时配图，并保存图源；对新增内容做去 AI 腔检查。
- 输出 `.typ`、`.pdf`、`.docx`；DOCX 公式为 OMML，并做渲染 QA。

## C. 局部授权

请求：「全文保持原样，只把第 3 节改得更好懂，并给它的算法加流程图。」

- 第 3 节进入局部生成模式；其余章节按转换模式保留。
- 图只加给第 3 节算法；不改其他正文，不给全篇补总结图。
- 去 AI 腔检查只作用于第 3 节；原文其他部分的生硬表达不改。
- 修改后从共同源重导出所有受影响格式。
- 同类请求「补一个例子」只授权新增该例；未点名章节不构成全文改写授权。

## D. 国标正文转换

请求：「按这个国标样式把说明导出 Word，只要文字表格附录，不要红头和署名。」

- 进入转换模式，选择 `gbt9704`。
- 输出包含 `.docx`，并按默认交付保留 `.typ` 与 `.pdf`。
- 保留文字、表格和附录；不加红头、发文字号、主送机关、署名、日期、印章或版记。
- 不称为完整国标公文认证；只有实际用原生 Word 检查后才能说原生 Word 已验证。
